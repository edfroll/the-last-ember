## Шаг 3. Инструмент перебора сидов — готов

**Что сделано.** `tools/seedmap.sh <outDir> <size> <stride> <seed…>` (Java `tools/seedmap/SeedMap.java` на серверном jar 26.3). Считает ванильные шумы рельефа и биомов по сиду без сервера и без генерации чанков: ~10 с на сид при области 3200×3200 с шагом 8 блоков (картинки 800×800). Реальная генерация через сервер даёт ~15 чанков/с, то есть ~45 мин на сид, для перебора не годится.

На сид выдаёт: `seed_N_height.png` (рельеф с тенями, глубина воды, сетка 400/800 блоков, красный крест = 0,0), `seed_N_biomes.png` (биомы, цвета ванильные), `seed_N_grid.json` (сетка высот и биомов для скоринга, в git не кладём, получается заново). Примеры: `docs/reports/seeds/`.

**Как проверено.** На сиде 2026 сравнил с реально сгенерированным сервером миром (100 случайных точек в ±120 блоков): биом совпал в 97/100 (остальные на границах биомов), высота верхнего блока совпала в 99/100 (расхождения: трава, снег, деревья). Наши оверрайды worldgen (руды, структуры) рельеф и биомы не меняют, поэтому ванильный сэмплер отражает мир с датапаком.

**Примеры (область 3200×3200, доля океана / макс. высота / главные биомы):**

| сид | океан | макс. Y | биомы |
|---|---|---|---|
| 1 | 61% | 148 | океаны, лес, равнины, снежная тайга |
| 42 | 61% | 203 | океан, лес, равнины, реки, болота |
| 2026 | 45% | 203 | равнины, лес, реки, тайга, саванна |
| 777 | 65% | 170 | тёплые океаны, лес, река, саванна |
| 31337 | 33% | 237 | лес, снежные равнины, тайга, снежная тайга, роща |

**Отличия от задачи.** Критериев отбора пока нет (придут как T-002). Скоринг (связность суши, расстояния между биомами, горы и т. п.) допишу по ним поверх `grid.json`. Инструмент можно расширить: шаг 4 блока, нужные ограничения по высоте, поиск сидов с заданным рельефом возле (0,0).

## Шаг 4. Автоматические скриншоты — предложение (внедрять не стал)

Сервер скриншотов не снимает, только клиент. Варианты:

1. **Реальный клиент 26.3 + управление сервера (рекомендую).** Камеру двигаем командами через RCON: игрок-наблюдатель в режиме spectator, `tp @s x y z yaw pitch` ставит точку и ракурс, `time set`/`weather` задают свет. Клиент стартует сразу в нужный мир: в манифесте 26.3 есть `--quickPlayMultiplayer <host:port>`, `--width/--height`. Снимок делает клавиша F2 (файлы в `screenshots/` клиента), нажатие шлёт скрипт через macOS (`osascript`/Quartz). Плюсы: ровно то, что увидит игрок (ресурс-пак, туман, 12 чанков). Минусы: нужен Accessibility-доступ для скрипта, окно клиента на экране, лаунчер Edward'а (Legacy Launcher) нужно уметь запускать с этими аргументами; верно для macOS-клиента, на сервере без экрана не заработает. Ориентир по скорости: 1–2 кадра в секунду после прогрузки чанков.
2. **Оффлайн-рендер по файлам мира (Chunky и подобные).** Не мод: автономная программа читает region-файлы и рисует сцену по JSON с позициями камеры. Без окна игры, пакетно, но это path-tracing с упрощённым освещением и без нашего ресурс-пака и настроения. Chunky 1.5.3 требует Java 25 и заявлена для 26.1; поддержку 26.3 нужно проверить отдельно (в поиске я её не нашёл). Годится для обзорных кадров рельефа, не для оценки атмосферы.
3. **Бот (mineflayer и др.)** Бот только двигается и общается, рендера нет. Годится как «оператор» для камеры вместо spectator-игрока, но скриншоты всё равно снимает клиент. Для 26.3 не проверял: в поиске нашёл только поддержку 26.1.2 в mineflayer.

**Что проверил, что нет.** Проверено: аргументы запуска клиента в манифесте 26.3. По Chunky и mineflayer данные из поиска, не из экспериментов. Не пробовал запуск клиента через пиратский лаунчер Edward'а.

## Обновление: шаг 4 реализован (вариант 1, но без нажатия клавиш)
Права macOS не потребовались: osascript отказал («not allowed to send keystrokes»), запись экрана тоже недоступна приложению. Поэтому вместо имитации F2 сделал маленький dev-агент для **локального** клиента (`-javaagent`, он не часть карты): по файлу-запросу вызывает штатный скриншот клиента, скрывает HUD и чат, закрывает меню. Клиент 26.3 берётся из установки лаунчера Edward'а, но запускается нашим скриптом из отдельной папки `server/client/`, его настройки не меняются.

Использование: `tools/screenshot.py shots.json` (список точек x/y/z, yaw/pitch, время суток, погода, HUD да/нет; камера — spectator, двигается `tp` через RCON). Кадр 2560×1440, ~8 с на кадр с ожиданием прогрузки чанков. Проверено на сиде 2026: обзор сверху, взгляд на восток, кадр с HUD — чистые, без чата и подсказок. Рендерится ровно то, что видит игрок (12 чанков, без шейдеров; ресурс-пак карты подключим, когда он появится).

Ограничения: окно клиента должно быть открыто на Mac (оно может быть позади других окон, но Mac не должен спать); работает только на macOS-клиенте с нашим скриптом запуска; запрос от Edward'а на Accessibility больше не нужен.
